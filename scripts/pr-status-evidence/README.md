# Working-status comparison driver

This isolated evidence branch checks out the exact source heads in `targets.json`, verifies their Git trees, and overlays two previously untracked test-only files. It never changes a tracked application file. The production timeline, LegendList, SVG branding primitive, stylesheet and `useTheme` hook render the captured interface. Conversation and working-state props are controlled by clearly labelled fixture controls; no native desktop or live provider run is claimed.

Each source runs once with normal Chromium motion preferences and once with reduced motion. The actual CSS animation runs continuously during capture. The fixture observes twenty positions over a full shimmer period, checks the shared timeline cadence and visible base color, and records four states in each mode: dark Thinking at 13px, dark Thinking at 18px, the unchanged semantic delivery icon at 18px, and light Thinking at 13px. The repaired state additionally requires the inline Synara SVG and relative mark sizing. Existing working-header wording and timer remain asserted.

The unchanged 18px assertion failed on both initial sources: fixture state had changed to 18px, but the retained production rows still rendered at 13px. The comparison now pins the repaired source and adds one screenshot per motion mode immediately before that same assertion. These observation images do not assert the rendered size. Before remains a genuine failed control with partial images; After must pass the original font, semantic status and motion assertions to complete all ten PNGs. No remount or Before-specific relaxed expectation is used.

Two additional control jobs run the exact two production browser regressions from repair `63c33e00238b4ca13aa52ecee29bb6494ed4f642` unchanged against the preceding `ca7345b440a7a2fd3d9ffa4637d708cc1a1519e8` and repaired heads. The pre-repair source lacks that test file, so only the byte-verified untracked test is overlaid; the repaired head uses its tracked file unchanged. Both cases run without test-name filtering. JSON reports must account for both tests with no skipped cases, and the actual Vitest and tee exits remain the job exits. An expected failing control is never converted into success.

The runner records source/tree/file Git identities, SHA256 hashes of every overlay and artifact, the immutable driver commit, original logs, and the actual Vitest and tee exits. An unsuccessful run remains unsuccessful. Failed recordings and partial screenshots retain their diagnostic classification until independently inspected and explicitly qualified for comparison. GitHub artifacts are inspected and hash-verified before any image or clip is published to a PR. Playwright records the entire browser context at 1280×900; the fixture viewport is 800×560, so recorder padding may appear in the raw video. No imagery is generated or redrawn.
